## 最上位方針

- iPhoneから開発指示、PRの確認、承認、監視をする。常時稼働PCは不要とする。
- 公開してよいプログラム、予想ロジック、API仕様、架空テストデータはPublicで管理する。
- APIキー、認証情報、私的個人情報、非許諾データ、実映像・原本をPublicに投入しない。
- 公開前検査に合格しない限り、GitHubへの送信を行わない。GitHub ActionsのCIは公開後の第二防壁にすぎない。
- 追加クラウド費用0円を原則にし、有料API/GPU/ライセンスの自動利用・課金を禁止する。
- 取得・保存・解析・学習・再公開は情報源と用途ごとの権利を確認してから行う。未確認は停止。
- 予測は発走前に凍結して結果と独立照合。後付け予想は本番精度に含めない。
- 自動投票・入金・追加入金・損失追跡目的の増額は対象外。未実証モデルはNO_BET。

## 情報分類と公開境界

| 種類 | Publicへの投入 | 管理 |
|---|---|---|
| コード・API仕様・架空テストデータ | 送信前審査後のみ可 | GitHub Public |
| 出走表、選手、オッズ、結果など実レース情報 | 取得・公開・保存の許諾と範囲を確認した場合のみ | 契約/権利に合わせて保管 |
| 過去動画、契約書、研究原本、内部ログ | 原則不可 | 非公開保存。保管禁止条件なら保管しない |
| 私的な氏名・連絡先・住所・口座・位置履歴・スクショ | 不可 | 原則収集せず、必要時のみ最小化 |
| APIキー、PAT、パスワード、秘密鍵、資格情報 | 絶対不可 | GitHub/Cloudflare Secrets等 |

公開されている選手名でも無条件の再配布権があるとは限らない。サイト閲覧可能と機械的な大量取得・AI学習可能も区別する。

## Publication Security Gate

GitHub PublicではPRブランチに送った時点で露出し得る。PR後のCIだけでは機密漏洩防止にならない。

1. PRE-PUBLISH: 書込前に非公開の一時作業域で差分、全ファイル、画像・バイナリ・アーカイブ、メタデータ、秘密、PII、権利区分を検査。検査できない場合もSEND_DENIED。GitHubコネクタ経由も例外なし。
2. POST-PUSH: GitHub Secret scanning、Push protection、Dependabot alerts、独立スキャン、CI、SAST、依存関係検査を設定可能な範囲で使用。検出漏れはあり得る。
3. PROTECT-MAIN: Publicのmainにブランチ保護、必須チェック、PR、レビュー、force push禁止と削除禁止。第三者PRのCIは原則read-only、秘密を渡さない。
4. INCIDENT: 漏洩時は秘密の失効・ローテーションを最優先。公開停止、履歴・ログ・artifact・forkを調査。履歴削除だけで解消とは扱わない。
5. AUDIT: 判定結果、対象ハッシュ、ツール版、時刻、独立レビュー証拠を保存。ただし監査ログに秘密の原文は残さない。

具体的な拒否・例外・テスト条件は SECURITY_POLICY_v0.4.md に定義する。

## ソース収集と時点管理

- SourcePermissionの判定単位: source_id × asset_type × action(fetch/store/train/display/export) × purpose × terms_version × validity。
- 未許諾・未確認ならHTTP自動取得を開始しない。規約変更時は再確認まで停止。
- 収集: 開催・レース、出走選手、選手ID、車番・級班・競走得点・直近成績、ライン、オッズ全組、会場条件、気象、公式結果・訂正、許諾済み映像。
- 各記録に情報源、原発表時刻、観測時刻、実取得時刻、保存時刻、権利版、スキーマ版、ハッシュを紐付ける。
- 発走後に分かった情報を予測前の特徴に混入しない。オッズの欠落を0倍として補完しない。
- 7車立て3連単210通り、9車立て504通り。組数欠落・締切・オッズ遅延なら買い目算出を停止。
- Race / Athlete / Entry / LineSnapshot / OddsSnapshot / WeatherSnapshot / ResultRevision / VideoAsset / FeatureSnapshot / Forecast / Decision / Audit等を時点付きで保存。

## AI予測エンジン

Model A: 競走得点・直近成績・基本脚質を利用する基準モデル。
Model B: ラインの先行争い、番手差し、捲り、主導権、ライン崩壊、先行選手の2・3着残り、別ライン3着浮上まで条件付きで評価。
Model C: 許諾済み過去動画の選手追跡・仕掛け・車間・失速等を追加し、独立テストでBより改善した場合のみ採用。

選手ごとの単純な勝率の掛算ではなく、3連単の全順序に非負の確率を割り当て、総和が1になることを検証。
過去→未来のwalk-forward検証、同一開催重複の排除、当該レースの結果・動画・事後オッズの混入禁止。
評価指標は多クラスlog loss、Brier、校正、Top-1/Top-8、会場・級班・車数別結果、市場基準との比較、サンプル数と不確実性。

## 映像解析

権利確認→映像メタデータ→ショット/カメラ切替→選手と自転車検出→個人追跡→車番と選手IDの結合→戦術イベント→モデル特徴。
遮蔽や映像外はUNKNOWN。較正されていない映像から正確な物理速度を断定しない。
IDF1、IDスイッチ、イベントのprecision/recall、別会場と別画角の未知映像を独立評価する。
映像を取得できないときにもModel Bを利用可能にする。

## 予想・買い目・資金

- 3連単は通常0～8点。設定で16・24・32点へ拡張可能。0点は正規の見送り。
- 仮の期待収益率は予測確率×予測時点の十進オッズ−1。ただし確率推定誤差とオッズ変動があり、プラスを保証しない。
- 未校正、データ不足、権利不足、オッズ欠損、締切後、発売中止時はNO_BET。
- 固定予算を使い切らず、負けを取り返すための自動増額もしない。
- 発走前予測のモデル版・使用特徴・オッズ時点・全順位確率・決定理由を凍結。確定結果と独立照合。

## iPhone UI・インフラ・統合

画面: 開催一覧、ライン・展開、3連単確率、オッズ観測時刻、NO_BET理由、動画解析、結果比較、取得権限、安全監視、費用監視。
事実とAI推測と事後分析は別ラベル。管理画面・非公開APIは認証/認可。秘密をログへ出さない。
小規模API/DBは無料枠のCloudflare Workers/D1/R2を検討、CIはGitHub Public標準Actionsを活用。無制限のGPU・保存量・ジョブ時間は想定しない。
RACE AIとはバージョン付き共通API（EventEnvelope / ForecastEnvelope / MarketOddsSnapshot / OutcomeEnvelope）で接続。
競輪の車番・ラインはsport_extension.keirin、ボートのコース等はsport_extension.boatに隔離。
認証情報や契約付き原本を両方のシステム間で自動共有しない。
